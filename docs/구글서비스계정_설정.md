# 구글 서비스 계정 설정 (사람이 직접 해야 하는 일)

GitHub Actions가 사람 로그인 없이 구글 드라이브에 쓰려면 서비스 계정이
필요합니다. muwon406과 분리하기로 했으므로 새로 만듭니다. 이 저장소는
public이라 GitHub Actions 실행 로그를 누구나 볼 수 있지만, 아래 절차대로
하면 키 원문이 로그에 찍히지 않습니다.

## 1. 구글 클라우드 프로젝트 준비

https://console.cloud.google.com/projectcreate 에서 새 프로젝트를
만듭니다(예: `auto-trading-sim`). 이미 쓰는 프로젝트가 있으면 그것을
써도 됩니다. 어느 쪽이든 다음 단계에서 그 프로젝트를 선택한 상태로
진행합니다.

## 2. 구글 드라이브 API 켜기

https://console.cloud.google.com/apis/library/drive.googleapis.com
화면 위에서 방금 만든 프로젝트를 고르고 "사용 설정" 버튼을 누릅니다.

## 3. 서비스 계정 만들기

https://console.cloud.google.com/iam-admin/serviceaccounts/create

- 서비스 계정 이름: `auto-trading-drive-writer` 같은 이름
- 역할(2·3단계)은 건너뛰어도 됩니다. 구글 드라이브 접근은 IAM 역할이
  아니라 4단계의 폴더 공유로 정해집니다.
- 만들고 나면 목록에 이메일 주소가 보입니다.
  `xxxxx@auto-trading-sim.iam.gserviceaccount.com` 같은 모양입니다.
  이 주소를 4단계와 5단계에서 씁니다.

## 4. 키 만들기

방금 만든 서비스 계정을 클릭 → 상단 "키" 탭 → "키 추가" → "새 키 만들기"
→ JSON 선택 → 만들기. JSON 파일이 자동으로 다운로드됩니다. 이 파일이
비밀값입니다. 이메일로 보내거나 채팅에 붙여넣지 말고 6단계에서 GitHub
비밀값으로만 등록합니다.

## 5. 서비스 계정을 공유 드라이브 멤버로 추가

`Auto_Trading` 폴더는 공유 드라이브 안에 있습니다. 폴더를 우클릭해서
공유하는 것으로는 부족합니다(2026-09-21에 실제로 이것 때문에 막혔습니다).
드라이브 자체의 멤버로 넣어야 합니다.

drive.google.com 왼쪽 메뉴의 "공유 드라이브"에서 `Auto_Trading`이 들어
있는 드라이브를 열고, 상단의 멤버 관리 아이콘을 눌러 3단계에서 확인한
서비스 계정 이메일 주소를 추가합니다. 역할은 "관리자" 또는 "콘텐츠
관리자"로 줍니다.

## 6. GitHub 저장소 비밀값으로 등록

https://github.com/uTaxx/Auto_Trading/settings/secrets/actions/new

- Name: `GDRIVE_SA_KEY_JSON`
- Secret: 4단계에서 받은 JSON 파일을 텍스트 편집기로 열어서 내용
  전체를 그대로 붙여넣습니다.
- "Add secret"을 누릅니다.

## 7. 도메인 위임 (새 종목을 완전히 자동으로 추가하려면)

5단계까지만 하면 이미 받아 둔 종목(파일이 있는 경우)은 잘 갱신됩니다.
다만 서비스 계정은 공유 드라이브 멤버여도 **새 파일을 처음 만들 때만**
"저장 용량이 없다"는 오류로 막힙니다(2026-09-21에 실제로 겪었고, 폴더를
새로 만들거나 있는 파일을 고치는 것은 문제없었습니다). 새 종목을 대시보드
버튼만으로 추가하려면 이 단계가 필요합니다.

1. GCP 콘솔의 서비스 계정 목록
   (https://console.cloud.google.com/iam-admin/serviceaccounts)에서
   서비스 계정을 클릭 → "세부정보" 탭의 "고유 ID"(Unique ID, 긴 숫자)를
   복사합니다. 이메일 주소가 아닙니다.
2. https://admin.google.com → 보안 → 액세스 및 데이터 제어 → API 제어 →
   "도메인 전체 위임 관리" → "새로 추가".
3. 클라이언트 ID에 1번에서 복사한 숫자를 입력하고, OAuth 범위에
   `https://www.googleapis.com/auth/drive`를 입력한 뒤 승인합니다.

이 저장소의 워크플로는 이미 `GDRIVE_IMPERSONATE_EMAIL=master@sondullab.com`로
설정돼 있어서, 도메인 위임만 걸리면 서비스 계정이 master@sondullab.com
명의로 파일을 만들어 이 문제가 사라집니다.

## 확인하는 법

`.github/workflows/update-prices.yml`을 GitHub Actions 탭에서
`workflow_dispatch`로 손으로 한 번 실행해 봅니다(symbols에 `SPY` 정도
넣고). 성공하면 구글 드라이브 `01_시세원본/SPY/daily.csv`가 생깁니다.
실패하면 실행 로그에 원인이 남는데, 키 원문은 찍히지 않으니 로그를
그대로 봐도 됩니다.
