# Auto_Trading 시스템 프로세스

작성일 2026-09-22. `시스템_설명서.md`와 같은 날, 같은 방식(코드를 직접
읽고 확인)으로 썼다. 이 문서는 "지금 실제로 도는 순서"와 "실거래로
가려면 새로 생겨야 하는 단계"를 나눠서 적는다.

## 지금 도는 과정 (전부 사람이 시작한다)

```
① 시세 수집               ② 전략 입력                ③ 계산 요청
사람이 종목 티커를          사람이 대시보드에서          사람이 "비교 계산" 또는
입력하고 버튼을 누름         매수 방식·변수·익절/손절을    "최적 조건 찾기"를 누름
   │                        직접 입력(또는 AI 프롬프트    │
   ▼                        복사해서 별도 대화에 물어봄)  ▼
GitHub Actions              │                          GitHub Actions
(update-prices.yml)         ▼                          (run-backtest.yml 또는
   │                     조회 시작일·종료일도            find-best-strategy.yml)
   ▼                     직접 입력(과거 유사 구간           │
야후 파이낸스에서            자동 탐색 결과를 가져다           ▼
일봉을 받음                 쓸 수도 있음)                구글 드라이브의 시세를
   │                                                    읽어 하루 단위로 계산
   ▼                                                       │
구글 드라이브에 저장                                         ▼
(01_시세원본/<종목>/                                     결과를 JSON(원본)과
daily.csv)                                              서식 있는 엑셀로
                                                         구글 드라이브에 저장
                                                         (02_백테스트결과/)
                                                            │
                                                            ▼
                                              ④ 결과 확인 (대시보드)
                                              표·그래프로 보거나 엑셀을
                                              직접 열어 봄. 필요 없으면
                                              결과와 엑셀을 함께 지움
                                                            │
                                                            ▼
                                              ⑤ 판단 (사람)
                                              "이 조합이 괜찮아 보인다"
                                              까지 사람이 결론 내고 끝남
```

같은 화면 동작이 전부 같은 방식을 쓴다. 사람이 대시보드에서 버튼을
누르면 n8n 웹훅이 GitHub Actions를 `workflow_dispatch`로 부르고,
대시보드는 그 실행이 끝날 때까지 10초 간격으로 상태를 물어보다가
끝나면 결과를 자동으로 다시 불러온다. **① ~ ③ 중 어느 것도 정해진
시각에 저절로 실행되지 않는다.** 매일 아침 시세를 받거나 밤에 최적
조건을 다시 계산하는 자동 일정은 없다.

## ⑤에서 멈춘다

지금 과정은 "사람이 결과를 보고 판단한다"에서 끝난다. 그 판단을 실제
주문으로 옮기는 절차가 없다. 아래는 ⑤ 다음에 새로 있어야 하는
단계들이다. 순서는 "이렇게 진행하면 된다"는 결론이 아니라, 빠진
조각을 나열한 것이다.

```
⑤ 판단 (사람) ──▶ [여기서 끝. 지금은 없음] ──▶ ⑥ ~ ⑩
```

- **⑥ 실거래용 계산으로 다시 검증.** `시스템_설명서.md` 3장의
  가정(환율 미반영, 비용 없음, 체결가=당일 종가 등)을 걷어낸 계산으로
  같은 조합을 다시 본다. 백테스트 성적이 그 가정 때문에 부풀려져
  있을 수 있어서, 가정을 걷어내면 결론이 달라질 수 있다.
- **⑦ 증권사 연결.** 계좌 조회·주문·체결 확인이 되는 API 연동.
  지금 이 저장소에는 없다.
- **⑧ 사람의 승인.** 매일(또는 정해진 주기로) "오늘 무엇을 얼마나
  살지" 후보를 내고, 사람이 확정하는 절차. 그냥 계산 결과를 그대로
  주문으로 바꾸지 않는다는 뜻이다.
- **⑨ 리스크 관리.** 장중에 가격을 감시해서 손절 조건에 닿으면 실제로
  파는 절차, 그리고 그 절차가 실패했을 때(주문 거절, API 오류)의
  대응.
- **⑩ 사후 대사.** 실제로 체결된 것과 계산이 예상했던 것을 맞춰
  보는 절차. 둘이 다르면 왜 다른지(체결가 차이, 슬리피지, 환율 변동)
  확인할 수 있어야 한다.

⑦ ~ ⑩에 해당하는 구조를 이미 실제로 운영하는 저장소가 이 계정에
따로 있다(`muwon406`, 국내 단기 매매). 다만 계좌·인증 키·자동 실행을
이 저장소와 분리해서 쓰고 있어서, 그 코드를 그대로 가져다 쓸 수는
없고 구조만 참고할 수 있다. 자세한 내용은 `시스템_설명서.md` 4장에
적었다.

## 데이터가 오가는 곳

- **구글 드라이브**: 원본 시세(`01_시세원본`), 계산 결과 JSON과
  엑셀(`02_백테스트결과`)을 저장하는 유일한 곳이다. 서비스 계정으로
  인증한다.
- **GitHub Actions**: 실제 계산(시세 수집, 백테스트, 최적화)이 도는
  곳이다. 전부 `workflow_dispatch`로만 실행된다.
- **n8n**: 대시보드와 GitHub Actions 사이를 잇는 웹훅
  (`AutoTrading_시세업데이트` 워크플로 하나, 경로 10개). 판단은 하지
  않고 그대로 전달만 한다.
- **GitHub Pages**: 정적 대시보드(`dashboard/`)가 나가는 곳.
