# Auto_Trading — 누적 매수 기법 전략 시뮬레이터

이 저장소는 `muwon406`(국내 단기 매매 시스템)과 완전히 분리된 새 프로젝트입니다.
계좌, 상태 저장소, GitHub Actions, n8n 워크플로를 공유하지 않습니다.

## 목적

미국 지수추종 ETF와 유망 섹터 ETF를 대상으로, 일회성 매수부터 적립식 매수,
이동평균선 조건부 매수까지 여러 매수·매도 방식을 과거 시세로 비교하는
백테스트 시뮬레이터를 만듭니다. 이후 일일 자동 매수 조건, 한국투자증권 API
연동까지 단계적으로 확장할 계획입니다.

## 지금 단계

1단계(시세 데이터 파이프라인)와 2단계(백테스트 비교 엔진)를 끝냈고,
둘 다 화면 하나(`dashboard/`, GitHub Pages)에서 씁니다. 저장소가 public이라
Pages를 그대로 쓸 수 있습니다.

- **시세 수집**: 종목을 입력하고 누르면 n8n 웹훅을 거쳐 `update-prices.yml`이
  야후 시세를 받아 구글 드라이브 `01_시세원본/<종목>/daily.csv`에
  저장합니다. 도메인 위임을 걸어 둬서 새 종목도 사람 개입 없이 처리됩니다.
- **수집 결과 조회**: 시세 수집이 실제로 끝났는지 구글 드라이브를 직접
  봅니다. 종목별로 daily.csv가 있는지, 마지막으로 언제 저장됐는지 보여주고,
  '내용 보기'를 누르면 거래일 수와 데이터 기간, 마지막 종가까지 확인할 수
  있습니다. n8n은 드라이브 조회만 대신하고, CSV 내용 계산은 화면(JS)에서
  합니다. **최근 2주·한 달·두 달 동안 값이 움직인 모양과 가장 비슷했던
  과거 구간**도 같이 보여줍니다(2026-09-21에 더함). 시작일을 0%로 맞춘
  누적 수익률 곡선끼리 견줘서 차이가 가장 작은 구간을 찾는 것이고, 과거에
  비슷한 모양이 있었다는 사실만 보여줄 뿐 앞으로 그렇게 된다는 뜻은
  아닙니다. **그 구간이 끝난 뒤 같은 길이만큼 실제로 어떻게 됐는지도
  같이 보여줍니다**(2026-09-21에 더함). 과거 구간은 이미 지난 일이라
  그 뒤에 값이 어떻게 움직였는지 알 수 있다는 점을 쓴 것입니다. 이
  값을 찾는 자리와 그 뒤 구간이 겹치지 않을 만큼 과거 데이터가 있어야
  계산되고, 부족하면 "자료 부족"이라고 적습니다. **과거 구간(그 뒤
  실제 흐름 포함), 지금 흐름, 그 과거 패턴을 지금 시점에 그대로 적용해
  본 예상 흐름을 한 그래프로도 보여줍니다**(2026-09-21에 더함). 과거
  구간의 마지막 날을 0%로 맞춰 앞뒤를 하나로 잇고, 지금 구간은 오늘
  종가를 0%로 맞춰서 같은 기준으로 겹쳐 볼 수 있게 했습니다. 점선으로
  그리는 예상 흐름은 과거 구간의 뒤쪽 절반을 그대로 오늘 이후로 옮겨
  그린 것일 뿐, 예측이 아닙니다.
- **시세 수집 완료 자동 확인**(2026-09-21에 더함): 수집 요청을 보내면
  화면이 GitHub Actions 실행 상태를 스스로 확인합니다. daily.csv의 수정
  시각만 보면 안 됩니다. 이미 최신이라 새로 받을 게 없는 날은 그 시각이
  안 바뀌는데, 그걸 "아직 안 끝났다"로 잘못 읽게 됩니다. 그래서
  `auto-trading-check-run` 경로로 그 워크플로의 최근 실행 목록을 직접
  받아, 요청 전에 없던 새 실행이 완료 상태가 될 때까지 10초 간격으로
  확인합니다. 끝나면 화면 문구가 바뀌고 2번 표도 자동으로 새로고침되며,
  브라우저 알림 권한을 허용해 뒀으면 알림도 뜹니다.
- **전략 비교**: `src/auto_trading/backtest.py`에 매수 방식 네 종류(일회
  매수, 적립식 매수, 적립식+이동평균선 조건, 등락률 기준 비중 조절)가
  있습니다. **전략의 세부 조건(회당 매수 금액, 매수 간격, 이동평균 기간,
  등락률 구간 같은 값)은 전부 화면에서 사람이 입력해야 계산됩니다.**
  코드가 몰래 기본값을 넣지 않습니다(`build_strategy`가 빠진 값을 오류로
  알립니다). 적립식 매수는 총자본을 횟수로 나누지 않고 회당 금액을 직접
  받습니다("나눠 살 횟수"는 총자본을 먼저 알아야 감이 잡히는 값이라
  직관적이지 않다는 지적을 받아 2026-09-21에 바꿨습니다). 등락률 기준
  비중 조절은 하락 구간뿐 아니라 상승 구간도 넣을 수 있습니다. 모든
  전략에 익절선과 손절선을 선택으로 걸 수 있고, 둘 다 기본값은 없습니다
  (비워 두면 그 조건은 안 씁니다). 최대 5개 전략을 견줄 수 있고,
  `run-backtest.yml`이 계산해서 02_백테스트결과에 JSON으로 남기면 화면이
  그 결과를 표와 그래프로 보여줍니다.

n8n 웹훅은 하나의 워크플로(`AutoTrading_시세업데이트`) 안에 경로
일곱 개로 몰아 뒀습니다: 시세 업데이트 요청, 시세 목록 조회, 시세 파일
내용 조회, GitHub Actions 실행 상태 조회, 백테스트 요청, 결과 목록 조회,
결과 내용 조회. "N8N은 최소 이용"이라는 원칙을 지키려는 것입니다. 실행
상태 조회 경로는 `workflow` 쿼리 파라미터로 어느 워크플로 파일을 볼지
받게 만들어서, 나중에 백테스트 완료 확인에도 같은 경로를 재사용할 수
있습니다.

다음은 실제로 종목을 더 모으고, 여러 조건으로 비교해 보면서 화면을
다듬는 것입니다.

## 원칙

- 최소한의 구조로 시작하고, 기능은 하나씩 검증하면서 늘립니다.
- 실제 주문과 연결되기 전까지는 백테스트와 데이터 수집에 집중합니다.
- 구글 드라이브, 텔레그램 봇, GitHub Actions 계정은 muwon406과 새로
  분리해서 씁니다.
