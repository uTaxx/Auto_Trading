# Auto_Trading — 누적 매수 기법 전략 시뮬레이터

이 저장소는 `muwon406`(국내 단기 매매 시스템)과 완전히 분리된 새 프로젝트입니다.
계좌, 상태 저장소, GitHub Actions, n8n 워크플로를 공유하지 않습니다.

## 목적

미국 지수추종 ETF와 유망 섹터 ETF를 대상으로, 일회성 매수부터 적립식 매수,
이동평균선 조건부 매수까지 여러 매수·매도 방식을 과거 시세로 비교하는
백테스트 시뮬레이터를 만듭니다. 이후 일일 자동 매수 조건, 한국투자증권 API
연동까지 단계적으로 확장할 계획입니다.

## 지금 단계

1단계(시세 데이터 파이프라인)와 2단계(백테스트 비교 엔진)를 끝냈고,
둘 다 화면 하나(`dashboard/`, GitHub Pages)에서 씁니다. 저장소가 public이라
Pages를 그대로 쓸 수 있습니다.

- **시세 수집**: 종목을 입력하고 누르면 n8n 웹훅을 거쳐 `update-prices.yml`이
  야후 시세를 받아 구글 드라이브 `01_시세원본/<종목>/daily.csv`에
  저장합니다. 도메인 위임을 걸어 둬서 새 종목도 사람 개입 없이 처리됩니다.
- **수집 결과 조회**: 시세 수집이 실제로 끝났는지 구글 드라이브를 직접
  봅니다. 종목별로 daily.csv가 있는지, 마지막으로 언제 저장됐는지 보여주고,
  '내용 보기'를 누르면 거래일 수와 데이터 기간, 마지막 종가까지 확인할 수
  있습니다. n8n은 드라이브 조회만 대신하고, CSV 내용 계산은 화면(JS)에서
  합니다. **최근 2주·한 달·두 달 동안 값이 움직인 모양과 가장 비슷했던
  과거 구간**도 같이 보여줍니다(2026-09-21에 더함). 시작일을 0%로 맞춘
  누적 수익률 곡선끼리 견줘서 차이가 가장 작은 구간을 찾는 것이고, 과거에
  비슷한 모양이 있었다는 사실만 보여줄 뿐 앞으로 그렇게 된다는 뜻은
  아닙니다. **그 구간이 끝난 뒤 같은 길이만큼 실제로 어떻게 됐는지도
  같이 보여줍니다**(2026-09-21에 더함). 과거 구간은 이미 지난 일이라
  그 뒤에 값이 어떻게 움직였는지 알 수 있다는 점을 쓴 것입니다. 이
  값을 찾는 자리와 그 뒤 구간이 겹치지 않을 만큼 과거 데이터가 있어야
  계산되고, 부족하면 "자료 부족"이라고 적습니다. **과거 구간(그 뒤
  실제 흐름 포함), 지금 흐름, 그 과거 패턴을 지금 시점에 그대로 적용해
  본 예상 흐름을 한 그래프로도 보여줍니다.** 과거 구간의 마지막 날을
  0%로 맞춰 앞뒤를 하나로 잇고, 지금 구간은 오늘 종가를 0%로 맞춰서
  같은 기준으로 겹쳐 볼 수 있게 했습니다. **지금 흐름은 오늘까지만
  실선으로 긋고 그 뒤는 아무것도 안 그립니다**(2026-09-21에 다시
  손봤습니다. 점선이 실선과 같은 색이라 마치 예측인 것처럼 보일 수
  있다는 지적을 받아, 점선을 회색으로 따로 빼고 "오늘" 표시를
  뚜렷하게 넣었습니다). 점선은 과거 구간의 뒤쪽 절반을 그대로 오늘
  이후로 옮겨 그린 참고용일 뿐, 예측이 아닙니다. x축에는 구간 시작을
  기준으로 며칠째인지를 적습니다(과거 구간마다 실제 달력 날짜가 달라서
  날짜 대신 일수로 맞췄습니다. 실제 날짜는 본문 글줄에 적습니다).
  **1위만이 아니라 3위까지 찾아서, 2·3위는 체크박스로 그래프에
  겹쳐 볼 수 있습니다**(2026-09-21에 더함). 순위마다 다른 색을 쓰고
  구간을 범례에 같이 적습니다. **종가를 날짜별로 보여주는 반응형
  그래프도 있고, 달러·원화를 바꿔 볼 수 있습니다**(2026-09-21에 더함).
  원화 환산에 쓸 미국 달러/원화 환율(`KRW=X`)은 `update-prices.yml`이
  요청한 종목과 같은 방식으로 `01_시세원본/KRW=X/daily.csv`에 항상
  같이 받아 둡니다. 종목 거래일과 환율 날짜가 정확히 안 맞을 수 있어서
  (증시 휴장일이 서로 다릅니다), 그날 이전의 가장 최근 환율을 그대로
  씁니다. `KRW=X`는 사람이 고른 종목이 아니라서 수집 결과 표에는
  안 보여줍니다.
- **시세 수집 완료 자동 확인**(2026-09-21에 더함): 수집 요청을 보내면
  화면이 GitHub Actions 실행 상태를 스스로 확인합니다. daily.csv의 수정
  시각만 보면 안 됩니다. 이미 최신이라 새로 받을 게 없는 날은 그 시각이
  안 바뀌는데, 그걸 "아직 안 끝났다"로 잘못 읽게 됩니다. 그래서
  `auto-trading-check-run` 경로로 그 워크플로의 최근 실행 목록을 직접
  받아, 요청 전에 없던 새 실행이 완료 상태가 될 때까지 10초 간격으로
  확인합니다. 끝나면 화면 문구가 바뀌고 수집 결과 조회 표도 자동으로
  새로고침되며, 브라우저 알림 권한을 허용해 뒀으면 알림도 뜹니다.
- **전략 비교**: `src/auto_trading/backtest.py`에 매수 방식 네 종류(일회
  매수, 적립식 매수, 적립식+이동평균선 조건, 등락률 기준 비중 조절)가
  있습니다. **전략의 세부 조건(회당 매수 금액, 매수 간격, 이동평균 기간,
  등락률 구간 같은 값)은 전부 화면에서 사람이 입력해야 계산됩니다.**
  코드가 몰래 기본값을 넣지 않습니다(`build_strategy`가 빠진 값을 오류로
  알립니다). 적립식 매수는 총자본을 횟수로 나누지 않고 회당 금액을 직접
  받습니다("나눠 살 횟수"는 총자본을 먼저 알아야 감이 잡히는 값이라
  직관적이지 않다는 지적을 받아 2026-09-21에 바꿨습니다). 등락률 기준
  비중 조절은 하락 구간뿐 아니라 상승 구간도 넣을 수 있습니다. 모든
  전략에 익절선과 손절선을 선택으로 걸 수 있고, 둘 다 기본값은 없습니다
  (비워 두면 그 조건은 안 씁니다). 최대 5개 전략을 견줄 수 있고,
  `run-backtest.yml`이 계산해서 02_백테스트결과에 JSON으로 남기면 화면이
  그 결과를 표와 그래프로 보여줍니다. **서식 있는 엑셀도 같이 남깁니다**
  (2026-09-21에 더함). 종목·전략 조합마다 하나씩
  `02_백테스트결과/<종목>/실행일자_종목명_분석기간_조건.xlsx`로, 이번
  비교 전체를 담은 것 하나를
  `02_백테스트결과/종목비교결과/실행일자_종목명복수_분석기간.xlsx`로
  올립니다. 종목별 파일은 그 조합의 요약과 날짜별 전체 흐름(현금,
  보유수량, 평가금액, 그날 매수금액·매도금액·매도유형(익절/손절),
  그날까지의 누적수익률 등)을 담고, 비교 파일은 이번에 계산한 모든
  종목·전략의 요약을 한 표로 모읍니다. 요약 표는 "전략" 한 칸이 아니라
  매수방식·매수금액·매수빈도·이동평균조건·등락구간·익절선·손절선으로
  나눠서 담습니다(코드에 가까운 문자열보다 읽기 쉽게, 2026-09-21에
  더함). 헤더에 배경색을 주고 금액은 천단위 구분, 수익률은 퍼센트
  서식과 양·음에 따른 글자색을 입혔습니다(`src/auto_trading/xlsx_report.py`).
  같은 날 같은 조건으로 다시 올리면 그 파일을 덮어씁니다(daily.csv를
  올릴 때와 같은 방식입니다). **화면의 결과 그래프에도 매수·익절 매도·
  손절 매도 시점을 점으로 표시합니다**(2026-09-21에 더함). x축에는
  거래일 몇 군데를 골라 날짜를 적습니다.
  **비교 계산 요청도 시세 수집과 같은 방식으로 완료를 자동으로
  확인합니다**(2026-09-21에 더함). 끝나면 문구가 바뀌고 비교 결과 탭도
  자동으로 새로고침됩니다.
- **최적 조건 찾기**(2026-09-21에 더함): 종목 하나와 총자본, 조회기간만
  정하면 매수 방식 네 종류의 여러 변수 조합을 한꺼번에 계산해서 수익률이
  가장 좋은 조합을 찾습니다. 변수 후보값(회당 매수 금액, 매수 간격 같은
  것)은 쉼표로 구분해서 넣고, 미리 채워 둔 값은 시작값일 뿐이라 바꿀 수
  있습니다. **"세부 조건은 전부 사람이 입력한다"는 원칙과 부딪히지
  않도록, 후보값 자체는 언제나 화면에 보이고 사람이 정한 목록 안에서만
  조합을 시험합니다.** 등락률 기준 비중 조절 매수는 구간을 하나로
  단순화해서 찾고, 여러 구간을 쓰려면 전략 비교 탭에서 직접 설정해야
  합니다. **익절선·손절선도 매수 방식마다 따로 후보값을 여러 개 넣을 수
  있습니다**(2026-09-21에 두 번 바꿨습니다. 처음에는 값 하나를 검색
  전체에 똑같이 적용했다가, 후보 목록으로 한 번 바꿨습니다. 그런데도
  "전략별로 익절선·손절선 옵션을 넣으라는 것이지 이 기본 설정 말고"라는
  지적을 받아서, 매수 방식마다 다른 변수와 같은 자리에 익절·손절 후보
  칸을 따로 두는 지금 모양으로 바꿨습니다. 매수 방식마다 어울리는
  익절·손절 폭이 다를 수 있기 때문입니다). 비워 두면 그 조건 없이
  계산합니다. **계산한 조합 전부를 수익률 내림차순으로 남기고, 1등만
  골라내지 않습니다.** 수익률만 보고 고르면 우연히 잘
  맞은 조합을 고르기 쉬워서, **최대낙폭(구간 안에서 자산이 최고점 대비
  가장 많이 빠졌던 폭)도 항상 같이 보여줍니다.** 이 값은 전략 비교의
  결과 표와 엑셀 보고서에도 함께 들어갑니다. 조합이 200개를 넘으면
  계산을 시작하기 전에 거부합니다(`src/auto_trading/optimize.py`의
  `MAX_COMBINATIONS`). 화면이 후보값을 바꿀 때마다 예상 조합 수를 미리
  계산해서 넘으면 요청 버튼을 막습니다. 결과 JSON은 전략 비교와 같은
  모양이라, 화면의 비교 결과 탭이 그대로 읽습니다(다만 조합이 많아
  일별 시계열은 담지 않습니다). `find-best-strategy.yml`이 계산해서
  02_백테스트결과에 `최적화_실행시각_종목명.json`으로 남깁니다.
- **유사 과거 불러오기**(2026-09-21에 더함): 전략 비교, 최적 조건 찾기
  두 탭 모두에 있는 버튼입니다. 눌러서 10·21·42거래일 중 하나를 고르면,
  DATA 수집 탭의 '내용 보기'로 이미 찾아 둔 1순위 유사 구간의 시작일·
  종료일을 조회기간 칸에 그대로 채워 넣습니다. 그 종목을 DATA 수집
  탭에서 먼저 열어 보지 않았으면(찾은 결과가 없으면) 그렇게 안내하고,
  다시 계산하지는 않습니다(같은 계산을 두 번 하지 않으려는 것입니다).
  이렇게 채운 기간으로 비교·최적화를 실행하고 비교 결과 탭에서 결과를
  보면, "이후 예측(과거 기록 기준)"이라는 글줄이 같이 뜹니다. 그
  구간이 끝난 뒤 실제로 어떻게 됐는지(이미 지난 과거라 알 수 있는
  값입니다)와, 전체 후보 몇 개 중 몇 번째로 비슷했는지를 적습니다.
  **한 번의 사례를 통계처럼 부풀리지 않습니다.** 반복해서 확인한
  숫자가 아니라는 문구를 항상 같이 넣고, 결과의 종목·조회기간이 마지막
  '유사 과거 불러오기' 선택과 정확히 같을 때만 이 글줄을 보여줍니다
  (사람이 기간을 손으로 바꿔서 계산했으면 더는 그 유사 구간과 상관없는
  결과이기 때문입니다).

n8n 웹훅은 하나의 워크플로(`AutoTrading_시세업데이트`) 안에 경로
여덟 개로 몰아 뒀습니다: 시세 업데이트 요청, 시세 목록 조회, 시세 파일
내용 조회, GitHub Actions 실행 상태 조회, 백테스트 요청, 결과 목록 조회,
결과 내용 조회, 최적 조건 찾기 요청. "N8N은 최소 이용"이라는 원칙을
지키려는 것입니다. 실행 상태 조회 경로는 `workflow` 쿼리 파라미터로
어느 워크플로 파일을 볼지 받게 만들어서, 시세 수집과 전략 비교와 최적
조건 찾기 완료 확인 셋 다 같은 경로를 씁니다(화면 JS의
`pollWorkflowRun` 하나가 세 곳에서 쓰입니다).

다음은 실제로 종목을 더 모으고, 여러 조건으로 비교해 보면서 화면을
다듬는 것입니다.

## 원칙

- 최소한의 구조로 시작하고, 기능은 하나씩 검증하면서 늘립니다.
- 실제 주문과 연결되기 전까지는 백테스트와 데이터 수집에 집중합니다.
- 구글 드라이브, 텔레그램 봇, GitHub Actions 계정은 muwon406과 새로
  분리해서 씁니다.
